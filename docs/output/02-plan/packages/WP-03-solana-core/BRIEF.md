## 1. Objective
Implement the one shared Solana dependency: a `SolanaCoreService` (DI-registered) that wraps RPC, the server hot
wallet, a hardened `sendAndConfirm`, Helius DAS reads and SIWS verification, plus its `FakeSolanaCoreService` for
other packages' tests; the wallet-link flow (challenge/verify routes and the `solana_wallet_links` entity); a status
route; and the browser `SolanaWalletProvider`. Every other package consumes this service through DI and never
instantiates `Connection` itself.

## 2. Acceptance criteria covered
- AC-1: `POST /api/solana_core/wallet-link/verify` accepts a valid SIWS signature for the issued nonce and rejects replay, wrong domain and expired nonce.
- Enables AC-2…AC-10 (every package calls `SolanaCoreService`).

## 6. Interfaces and contracts
Provided (verbatim from `docs/CONTRACTS.md` / Q-API-02; do not rename members):
```ts
interface SolanaCoreService {
  cluster(): 'devnet'|'mainnet-beta'|'localnet'
  connection(): Connection                       // web3.js 1.x
  hotWallet(): { publicKey: PublicKey; sign(tx): Promise<Transaction> }
  sendAndConfirm(tx, opts?): Promise<{ signature: string; slot: number }>
  getTransaction(signature): Promise<ParsedTransactionWithMeta|null>
  getTokenBalance(owner, mint): Promise<bigint>
  getAssetsByOwner(owner, opts?): Promise<DasAsset[]>  // Helius DAS; NFTs incl. compressed
  verifySiws(message, signature, expectedNonce): Promise<{ address: string } | null>
}
```
Additional, allowed extensions (additive only): `searchAssets(params: DasSearchParams): Promise<DasAsset[]>`,
`getLinkedWallets(userId, tenantId, organizationId): Promise<SolanaWalletLink[]>`.
`DasAsset` = `{ id: string; interface: string; ownership: { owner: string; frozen: boolean }; grouping: { group_key: string; group_value: string }[]; content?: { metadata?: { name?: string; attributes?: { trait_type: string; value: string }[] } }; token_info?: { balance?: string; decimals?: number } }`.
`sendAndConfirm` opts: `{ signers?: Keypair[]; commitment?: 'confirmed'|'finalized'; maxRetries?: number /* default 3 */; priorityFeeMicroLamports?: number /* default: Helius estimate, fallback 1_000 */; skipSimulation?: boolean }`.
DI name: `solanaCoreService` (`asFunction(createSolanaCoreService).singleton()` — one `Connection` per process). Tests use `FakeSolanaCoreService` (in-memory wallets, balances, assets, canned transactions, recorded `sendAndConfirm` calls).

Entity `solana_wallet_links` (table name): `id uuid pk`, `tenant_id uuid`, `organization_id uuid`, `user_id uuid null`, `customer_id uuid null` (at least one of the two set), `wallet_address text` (base58, unique per tenant+address), `wallet_name text null`, `verified_at timestamptz`, `last_siws_nonce text null`, `created_at`, `updated_at`, `deleted_at`.
Routes: `POST /api/solana_core/wallet-link/challenge` → `{ nonce, message, expiresAt }` (auth required; nonce stored server-side in cache/DB keyed by user, 5-minute TTL); `POST /api/solana_core/wallet-link/verify` body `{ message, signature, walletName? }` → `{ walletAddress, verifiedAt }` or 400 `SIWS_INVALID` / `NONCE_EXPIRED` / `DOMAIN_MISMATCH` / `NONCE_REUSED`; `GET /api/solana_core/status` → `{ cluster, rpcOk, slot, hotWallet: { address, lamports }, programId, treasuryWallet, usdcMint }` (feature `solana_core.view`); `GET|DELETE /api/solana_core/wallet-links`.
Event: `solana_core.wallet.linked` `{ walletLinkId, walletAddress, userId?, customerId?, tenantId, organizationId }` with `clientBroadcast: true`.
Env keys read: `SOLANA_CLUSTER`, `SOLANA_RPC_URL`, `HELIUS_API_KEY`, `SOLANA_HOT_WALLET_SECRET`, `AEGIS_PROGRAM_ID`, `TREASURY_WALLET`, `USDC_MINT`, `PUBLIC_BASE_URL`.

## 7. Step-by-step implementation guide (one commit per step)
1. `config.ts` with Zod schema; secret fields never logged; unit test for missing/invalid keys. Commit.
2. **Interface + fake first** (day 2, push immediately so WP-04/05/06 can compile): `services/solana-core.service.ts` exporting the interface and types, `services/fake-solana-core.service.ts` with full in-memory behaviour, `index.ts` re-exporting both and `metadata`. Commit `feat(solana_core): service interface and fake`.
3. `services/hot-wallet.ts`: parse `SOLANA_HOT_WALLET_SECRET` as base58 or JSON byte array into a `Keypair`; expose `publicKey` and `sign`; never expose the secret. Commit.
4. `services/tx-sender.ts`: `sendAndConfirm` = get latest blockhash (`confirmed`) → set `feePayer` = hot wallet unless preset → `simulateTransaction` (unless `skipSimulation`) → `ComputeBudgetProgram.setComputeUnitLimit(ceil(unitsConsumed*1.1))` + `setComputeUnitPrice(priority)` where priority comes from Helius `getPriorityFeeEstimate` (POST to the RPC URL, method `getPriorityFeeEstimate`) with fallback → sign → `sendRawTransaction({ maxRetries: 0 })` → poll `getSignatureStatuses` until `confirmed` or `lastValidBlockHeight` passed → on expiry rebuild with a fresh blockhash up to `maxRetries` → return `{ signature, slot }`; structured log line `solana.tx.sent`. Commit.
5. `services/das-client.ts`: `getAssetsByOwner(owner, { page, limit ≤ 1000, showFungible, showZeroBalance })` and `searchAssets(params)` over the Helius RPC URL; simple token-bucket limiter (2 req/s); typed `DasAsset`. Commit.
6. `services/siws.ts`: build the SIWS message with `createSignInMessage` (`domain` = host of `PUBLIC_BASE_URL`, `statement` "Link this wallet to <tenant name> in Aegis Mercato", `nonce`, `issuedAt`, `expirationTime` +5 min); `verifySiws` with `verifySignIn` from `@solana/wallet-standard-util`, plus `signMessage` fallback (same text, verify with `tweetnacl`/`@noble/ed25519` against the address). Commit.
7. `createSolanaCoreService(config)` wiring the above, `getTransaction` with `maxSupportedTransactionVersion: 1`, `getTokenBalance` via `getParsedTokenAccountsByOwner` filtered by mint (sum of amounts as bigint), `di.ts` registration. Commit.
8. `data/entities.ts` (`SolanaWalletLink`) + `data/validators.ts`; `yarn generate && yarn db:generate` (review the migration, commit it) `&& yarn db:migrate`. Commit.
9. Routes: `api/openapi.ts`, `wallet-link/challenge`, `wallet-link/verify` (nonce stored via the cache package or a `solana_wallet_link_nonces` table — pick cache if `@open-mercato/cache` offers TTL, otherwise table; one-time use), `status`, `wallet-links` (`makeCrudRoute` list/delete, `indexer: { entityType: 'solana_core:wallet_link' }`). Emit `solana_core.wallet.linked` on verify. Every route exports `metadata` and `openApi`. Commit.
10. `frontend/SolanaWalletProvider.tsx` (`ConnectionProvider` + `WalletProvider` with Phantom/Solflare/Backpack via Wallet Standard auto-discovery, `WalletModalProvider`, `autoConnect`), `useWalletLink()` hook (`challenge` → `signIn` if supported else `signMessage` → `verify`). Commit.
11. `acl.ts` (`solana_core.view`, `solana_core.manage`), `setup.ts`, `i18n/en.json`, `README.md`. `yarn mercato auth sync-role-acls && yarn mercato configs cache structural --all-tenants`. Commit.
12. Tests (TESTS.md), full validation set, `REPORT.md`, `STATUS.md`; push; remove worktree.
